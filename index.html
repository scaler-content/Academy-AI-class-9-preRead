OpenClaw, an Agent That Lives on Your Machine

Run a personal agent locally, work with file-based memory, automate messages, and add security boundaries

Class 9AI and AgentsPre-Read

1. Welcome

The agents in earlier classes ran inside a workflow or a hosted environment. OpenClaw brings the agent onto your own machine, where it can work with files, run commands, connect to chat channels, and perform scheduled tasks. That flexibility also creates new risks. This session explores how OpenClaw is structured, how to set it up, and how to secure the access it receives.

What to keep in mindThis pre-read introduces the ideas and vocabulary you will use in class. The hands-on build and detailed demonstrations happen during the session.

As you read, think about what an agent should be allowed to do, what information it needs, and where a person should remain in control.

2. From building agents to owning one

In Class 7, you learned the think, act, observe, repeat loop. In Class 8, you built that loop in n8n. OpenClaw moves the agent onto your own machine, where it can work with local resources and keep its memory in files you can inspect.

Runs locally

The agent runs on your machine rather than only inside a hosted workflow.

File-based memory

Workspace files hold instructions, notes, and memory that a person can inspect.

More access, more responsibility

An agent that can touch files and accounts needs clear permission and security boundaries.

Keep in mindThe same capabilities that make a personal agent useful can also make mistakes more consequential.

3. What OpenClaw is and what is inside it

OpenClaw is an open-source personal AI agent. You install it, connect a model, and run it as a background process. You can communicate through a browser dashboard or supported chat channels.

Gateway

The always-running process connecting chat channels, the dashboard, scheduler, and agent.

Channels

The communication routes into the agent, such as a browser dashboard or Telegram.

Agent and tools

The agent loop and capabilities such as reading or writing files and running commands.

Skills and plugins

Additional capabilities that can be added to the agent.

Workspace

Files that store the agent’s instructions, notes, and memory.

Automations

Scheduled jobs that can run without a new user message.

Keep in mindThe model provider is a swappable component. OpenClaw is the surrounding Gateway, tools, workspace, and automation system.

4. Install it and say hello

The setup sequence checks the Node.js version, creates a Gemini API key, installs OpenClaw, runs the onboarding wizard, and starts a conversation. The script recommends using a personal laptop rather than a machine containing company data.

Node.js

Check that the installed version meets the version requirement in the class script.

API key

Create a Gemini API key and treat it like a password.

Onboarding

Choose the model provider and configure whether OpenClaw runs in the background.

Keep in mindNever paste an API key into a chat, screenshot, or Git repository. If a key leaks, replace it and revoke the exposed one.

5. Memory: files you can read

OpenClaw uses workspace files to hold instructions, notes, and memory. Because these are ordinary files, you can inspect what the agent has stored rather than treating memory as an invisible mechanism.

Workspace files

Files that provide the agent with instructions and context.

Inspectable memory

A person can open and review the stored notes.

Keep in mindReadable files make memory easier to inspect, but they do not automatically make every stored fact correct or appropriate to retain.

6. Build a study-notes helper

The class uses a practical study-notes task to show how an agent can work with files. You describe the intended outcome and the agent uses its available capabilities to create or organise notes.

Task

State the desired outcome clearly.

Access

Give the agent only the files and tools it needs.

Review

Check the files it creates or changes.

Keep in mindTreat file-writing as a real action. Review the result and avoid giving broad access to folders that contain unrelated or sensitive material.

7. Telegram and automations

A messaging channel lets you communicate with the agent outside the local dashboard. Scheduled jobs allow the agent to initiate a message rather than waiting for a new prompt.

Telegram channel

A route for sending messages to and receiving messages from the agent.

Scheduled job

An automation that runs at a configured time or interval.

Keep in mindAn agent that can message you first needs clear rules about what it may send and when.

8. Security: what has gone wrong and how to harden it

The class examines failures and security incidents, then applies safeguards. Important areas include permissions, exposed services, untrusted instructions, credentials, and the code behind skills and plugins.

Least privilege

Give the agent only the access required for its task.

Credential protection

Keep API keys and tokens out of prompts, screenshots, and repositories.

Network exposure

Avoid exposing local services unnecessarily.

Skill review

Inspect code and capabilities before installing or enabling them.

Keep in mindPopularity is not the same as safety. The agent can read files, write files, and run commands, so the machine and data it can access matter.

9. Keep the keys elsewhere: OpenClaw and n8n

The class separates the personal agent from workflows that hold credentials or perform controlled external actions. n8n can serve as a guarded action layer, with clearer workflow steps and approval points.

OpenClaw

A personal agent that works with local resources.

n8n

A workflow layer for controlled actions and credential handling.

Keep in mindKeep sensitive credentials in the system designed to manage them, and place approval or validation checks before consequential actions.

10. A Few Terms to Know

These terms will help you follow the explanations and activities in the session.

GatewayThe always-running OpenClaw process that connects chat channels, the dashboard, the scheduler, and the agent.
WorkspaceA folder of files—often Markdown—that stores the agent’s instructions, notes, and memory in a form a person can inspect.
ChannelA way to communicate with the agent, such as the browser dashboard or a supported messaging application.
AutomationA scheduled job that runs without a new user message and can allow the agent to contact the user first.
Human-in-the-loopA design in which a person reviews or approves an action before it is carried out by an automated system.
What you’ll walk away withYou’ll be able to describe OpenClaw’s main components, install and interact with a personal agent, understand file-based memory and scheduled messaging, and identify safeguards for credentials, tools, permissions, and external actions.
